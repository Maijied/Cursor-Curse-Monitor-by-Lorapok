## Summary

Fixes two Mission Control issues reported on mobile:

1. **Discord deployment notifications not firing** — CI never called `discord-deployment-notify.mjs`, and KV webhook sync only ran manually from cred vault.
2. **Invited admins blocked without master email** — Team invites wrote Firestore first; API allowlist (ADMIN_KV) sync could fail silently, so `invite-check` / `auth/me` returned 403 for non-master users.

## Discord notifications

- Run `scripts/sync-discord-cred-vault.mjs` during `deploy-infra` admin deploy (writes `integrations:discord` in ADMIN_KV).
- Post deploy status cards from CI after **Deploy Admin Panel** and **Deploy Marketing Website** via `discord-deployment-notify.mjs`.
- Load `DISCORD_DEPLOYMENT_WEBHOOK` from cred vault / `admin-production` secret fallback in CI.

## Admin access (non-master)

- **Team invite order:** sync `/api/admins` (KV allowlist + RBAC) **before** Firestore mirror.
- **Legacy repair:** on Team page load, reconcile Firestore-only admins into KV automatically.
- **Login:** Google sign-in now runs the same invite-check gate as password/magic link.
- **RBAC:** `admin` role gains `integrations.write` so delegated admins can save/test Discord hooks in Settings.
- **Resilience:** `tryGetMasterEmail()` + safer invite-check when master env is missing.
