## Problem

KV daily write quota (~1,000/day on Workers Free) causes errors everywhere — stats refresh, settings saves, automation, mail paths.

## Fix

### Global KV degrade (#248 follow-up)
- Early `shouldBlockKvWrites()` guard before marketplace fetches and config writes
- Settings APIs return **200** with `{ degraded: true, kvWritesPaused }` instead of **503**
- Stats refresh skips silently when quota blocked

### Firestore tertiary fallback (new)
When KV quota is exhausted:

| Layer | Behavior |
|-------|----------|
| **Writes** | D1/R2 → KV (if OK) → **Firestore** (`admin-kv-fallback`, `system-logs`) → graceful degrade |
| **Reads** | KV → **Firestore** on miss → env defaults |

Collections: `admin-kv-fallback` (mirrored KV keys), `system-logs` (append-only when D1/KV unavailable).

### Deploy prerequisite
Set Pages secret **`FIREBASE_SERVICE_ACCOUNT_JSON`** (service account JSON) and deploy Firestore rules (`firebase deploy --only firestore:rules`). Without it, KV-quota fallback degrades gracefully but Firestore tier is skipped.

## Tests
17+ vitest tests (kv-put, firebase-store, stats-refresh-quota) — all passing.

## After merge
1. Add `FIREBASE_SERVICE_ACCOUNT_JSON` to Cloudflare Pages production
2. Deploy admin Pages
3. Pause stats refresh until UTC reset if quota still exhausted today
